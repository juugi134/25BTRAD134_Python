ONE COMMAND TO RUN LOCALLY ON WINDOWS:
--------------------------------------
Open your terminal (PowerShell or Command Prompt) in this folder and run:

    .\run_windows.bat

(Or simply: .\start.bat  or  .\.venv\Scripts\python.exe start.py)

You can also double-click `run_windows.bat` in File Explorer.

This one command will:
1. Detect your Windows Python & virtual environment (`.venv\Scripts\python.exe`).
2. Verify all dependencies from `requirements.txt`.
3. Start the FastAPI server on http://localhost:8000/ with live reload.
4. Automatically open your browser to the web studio.

To generate a public shareable link on Windows:
    .\share_public.bat

Press Ctrl+C in your terminal when you want to stop the server.


ONE COMMAND TO RUN ON MAC / LINUX:
----------------------------------
Open your terminal in this folder and run:

    ./start.sh

(Or simply: python3 start.py)


DEPLOYING TO A REAL WEBSITE (PRODUCTION CLOUD):
----------------------------------------------
The app is built to run on a real public website with ZERO code changes:

Option A — Unified Full-Stack Cloud Host (Render / Railway / Fly.io / Heroku):
1. Push this folder to a GitHub repository.
2. In Render or Railway, create a new "Web Service" from your repo.
3. It detects the included `render.yaml` and `Procfile` automatically:
   - Build: `pip install -r requirements.txt`
   - Start: `uvicorn app:app --host 0.0.0.0 --port $PORT`
4. Your website is instantly live at your public HTTPS domain (e.g. `https://your-app.onrender.com`).
   FastAPI serves the entire frontend and backend from the same domain.

Option B — Split Architecture (GitHub Pages frontend + Cloud backend):
1. Deploy the backend on Render/Railway as above.
2. Open `docs/config.js` and set:
   window.SCENEGRAPH_API_BASE = "https://your-backend.onrender.com";
3. Enable GitHub Pages in your repo settings pointing to `/docs`.

Both local and cloud setups share the exact same files and database models.
